# Sunrise PDF PRO Web R40 DEV3 — 일괄 변환 및 인계

## 이번 작업
- 브라우저 로컬 rhwp 0.8.7 레이아웃 + SVG→PDFKit 경로를 사용한다. 기본값은 글자·도형 보존이며 허용되지 않은 페이지를 이미지로 자동 대체하지 않는다. 별도로 사용자가 선택할 때만 전체 페이지 이미지 출력이 가능하다.
- HWP/HWPX 다중 선택·추가·순차 변환, 파일별 상태/오류/삭제/미리보기/다운로드, 취소·재시도, 완료한 PDF의 ZIP 다운로드를 구현했다. 동일 이름에는 번호를 붙인다. ZIP 원본 데이터가 총 256MiB를 넘으면 개별 다운로드를 이용한다.
- OFL 라이선스 Nanum Gothic/Myeongjo 글꼴의 일반/굵게 4개를 동봉해 글꼴 부족 시 자동 공급한다. 글꼴을 직접 제공하면 우선 사용한다. 글꼴 대체 시 해당 파일에 표시한다. 화면 조판과 PDF 출력 양쪽에 같은 대체 글꼴을 적용한다. 글꼴 파일 및 라이선스는 browser-local/public/fonts 에 있다.
- 홈은 문서 선택·목록·출력 설정·진행률·결과 다운로드 중심으로 재배열했다. 인쇄 보조 경로에도 제공 글꼴을 연결했다.

## 실제 검증한 범위
- 독립 단위/계약 검사 41개 통과: 일괄 처리 실패 격리, 취소 후 결과 보존, ZIP 내용 및 중복 이름, 기존 폰트·SVG 안전 검증과 혼합 용지 제한 등.
- Vite 프로덕션 빌드 및 배포 자산 검증 통과, WASM과 글꼴 해시 확인, Worker 글꼴 경로 GET/HEAD와 POST 차단 검사 통과.
- 브라우저: 공개 HWP 샘플 사본 2개 동시 선택 → 순차 2개 성공, 글꼴 대체 표시, 각 다운로드 및 ZIP 링크 생성 확인. 실제 ZIP 다운로드 후 바이트 비교는 브라우저에서 별도 수행하지 않았으며 ZIP 내용은 단위 테스트로 검증했다.
- rhwp CLI로 기존 공개 HWP 샘플에 쪽 나눔을 삽입해 2쪽임을 확인한 다음 브라우저에서 변환하여 결과 화면에 2쪽 표시를 확인했다. 생성 PDF의 각 쪽 텍스트 및 원본과의 시각적 일치도는 아직 독립적으로 검증하지 않았다.
- HWP와 HWPX 동시 선택: HWP 성공, HWPX는 TEXT_LENGTH_ADJUST_UNSUPPORTED 로 실패를 표시하고 다른 파일의 완료 결과는 보존했다. 해당 HWPX에 대한 PDF 생성은 성공하지 않았다.

## 미완료 및 제한
1. rhwp 공식 native export-pdf 자체를 웹에서 구동하는 연결은 미완료다. 현재는 rhwp WASM의 SVG 출력과 별도 PDFKit을 연결한다. 공식 CLI를 Worker에서 직접 실행할 수 없고 공개 WASM에 PDF 내보내기 API가 없다. CLI 독립 시험 성공을 웹 기능 완성으로 취급하지 않는다.
2. HWPX SVG의 textLength/lengthAdjust를 기본 벡터 PDF로 충실히 표현하는 처리와 독립 검증이 필요하다. 현재는 명시적 실패이며 사용자가 요청하지 않은 이미지 대체는 없다.
3. 여러 페이지와 각기 다른 용지·표·도형·글꼴을 포함한 실제 문서에서 출력 PDF의 페이지 수, 텍스트 추출, 이미지 포함 여부, 원본 대비 시각적 품질을 검증해야 한다. 현재 2쪽 샘플의 화면상 쪽 수만 확인했다.
4. rhwp는 한컴 공식 엔진이나 Hancom COM이 아니며, 서로 결과가 완전히 일치한다는 검증이나 보장은 없다. 대체 글꼴과 미지원 구성요소로 레이아웃 차이가 날 수 있다. 원본 글꼴을 선택할 수 있으나 글꼴 권리 및 문서 지원 여부는 별개다.
5. 기본 변환은 1~120쪽 제한이 있다. 문서 크기에 고정 상한은 없지만 기기 메모리에 의존한다. 인쇄 보조 기능은 혼합 용지 문서를 제한한다.
6. 공개 서비스 배포, 배포된 웹 화면, 실제 사용자 문서 및 한컴 COM 결과와의 비교는 이번에 수행하지 않았다. 운영 배포용이 아닌 개발 체크포인트다.

## 실행
`npm --prefix browser-local ci --ignore-scripts` 후 `npm --prefix browser-local run build` 및 `npm --prefix browser-local run verify:dist`. Worker 통합 배포 구성은 기존 프로젝트 절차를 따른다. 배포 전 `node scripts/verify-browser-build.mjs`는 빌드 HTML을 app.html로 복사한다.
