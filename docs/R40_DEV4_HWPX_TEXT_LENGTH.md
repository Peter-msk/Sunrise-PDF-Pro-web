# R40 DEV4 HWPX 글자 폭 처리 인계

이전 브라우저 HWPX 샘플 실패 원인은 rhwp SVG에서 개별 ASCII 글자에 지정한 `textLength` 및 `lengthAdjust="spacingAndGlyphs"`를 검사 단계가 무조건 거부한 것이었다. 고정된 svg-to-pdfkit 0.1.8은 glyph 수평 폭 조정을 지원한다. 이번 변경은 독립적인 ASCII 한 글자, 양의 유한한 고정 px/숫자 폭, `spacingAndGlyphs`만 허용한다. 다중 글자, 중첩 글자, 한글 및 다른 문자 조합, 기타 폭 조정은 검증 전까지 계속 거부한다. 기본 글자·도형 보존 출력에서 이미지 자동 전환은 없다.

검증: 브라우저에서 이전 실패 HWPX와 2쪽 HWP를 동시 선택해 두 파일의 변환 성공과 ZIP 링크 생성을 확인했다. 실제 브라우저 PDF/ZIP 다운로드 시도는 도구 타임아웃으로 파일을 확보하지 못해 실제 결과 PDF의 페이지별 글자 추출, 이미지 여부, 원본 대조는 수행하지 못했다. 별도의 SVG-to-PDFKit 실 PDF 시험에서는 단일 M의 지정 폭 10pt와 40pt를 pdftotext bbox로 확인하고 페이지 이미지가 없는 점을 확인했다. 관련 코드 테스트 33/33 PASS; 프로덕션 빌드, 폰트/WASM 검증 및 Worker 경로 검증 PASS. 출력 화면의 글꼴 대체 표시가 활성화되어 있었다.

미완료: rhwp 네이티브 PDF 출력의 웹 연동은 아직 없다. HWPX의 다중 글자 및 한글 폭 조절은 지원 확대와 개별 검증이 필요하다. 실제 생성 PDF 페이지 수·글자 추출·이미지 유무·표와 도형 위치·한컴 COM PDF와의 시각 차이를 검증해야 한다. 문서에 따라 지원 실패 가능성이 있으며 한컴 엔진과 동일성을 주장하지 않는다. 운영 배포는 하지 않았다.
