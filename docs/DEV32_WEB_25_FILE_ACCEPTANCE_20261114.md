## DEV32 이번 변경
1. 브라우저 탭 내부 큐에서 직접 파일 순번, 형식, 상태, 현재 단계, 경과시간, 표준 오류코드, 허용된 SVG 필터 오류 분류(흐림·합성 등), PDF 페이지/벡터/이미지 쪽 수를 추출한다.
2. 파일명·경로·원본 문서·실제 글꼴·오류 자유문장을 포함하지 않는다.
3. 사용자가 [실기 검증 보고서 저장]을 눌러야만 해당 탭에서 JSON 다운로드를 요청한다. 자동 업로드·Cloudflare D1 기록·외부 API 호출을 하지 않는다.
4. 변환 작업이 지속되는 동안에도 현재 진행 상태의 스냅샷을 저장할 수 있다.
5. professional 기본·fail-closed, explicit hybrid-filter/compat-raster, 완료 PDF 보존, 개별 실패 재시도/일괄 명시적 복구 정책은 변경하지 않는다.

## Windows Chrome 사용자 실기 순서
1. Windows Chrome에서 Dev32 검증용 빌드를 연다. 배포된 운영판과 섞지 않는다.
2. 동일한 원본 25개를 같은 순서로 선택하고 변환 시작 전 [실기 검증 보고서 저장]을 눌러 queued=25인지 확인한다.
3. 기본 professional 모드 변환을 실행하고, 진행이 2분 이상 멈춘 것으로 보일 경우 보고서를 저장한 뒤 브라우저 작업 관리자·메모리·탭 visibility와 함께 확인한다. 단, 앱을 종료하거나 강제 취소하기 전 우선 상태를 기록한다.
4. 실행이 끝나면 다시 JSON 보고서를 저장하여 정확한 전체 상태 합이 25인지, 성공 13/실패 8/대기 4처럼 서버 이벤트만으로 추정한 값이 아닌 실제 큐 상태인지 확인한다.
5. SVG_FILTER_EFFECT_UNSUPPORTED 오류가 표시된 HWP/HWPX만 사용자가 직접 [실패 파일 N개만 복구]를 눌러 명시적 hybrid-filter를 재시도한다. 이전 성공 파일은 재생성되면 안 된다.
6. PDF마다 페이지 개수, 텍스트 선택/검색(벡터 쪽), 미지원 필터를 이미지로 대체한 페이지, 표·도면·그림·글꼴·줄바꿈·여백을 원본과 비교한다.
7. 같은 오류가 hybrid-filter에서도 남는다면 전체 페이지 이미지 PDF를 **명시적으로 선택**하고 결과의 검색 불가능성·시각 품질을 사용자에게 명확히 고지한다.

## 수락 게이트
- 고유 입력 25개가 큐에 정확히 등록됨; 파일별 상태 합=25; 누락된 작업 없음.
- 실패 파일 복구/재시도는 성공 파일·다른 대기 파일의 PDF를 수정하지 않음.
- 완성 PDF는 헤더·xref·trailer, 페이지 수, 바이트 수 검사 통과. 미완성 PDF를 다운로드 가능한 성공으로 표시하지 않음.
- 실제 25개 각 원본과 PDF의 글자·표·이미지·줄바꿈·페이지 경계 수락 확인.
- 성능 회귀·재현 가능한 일시정지·서체 임베딩 차이·원본 대비 시각적 차이 없음을 별도 체크.
- 보안/개인정보: 원본과 사용자 파일명·글꼴 파일을 서버에 전송하지 않음.
- 본 개발은 코드와 독립 QA 단계까지만 진행. 운영 배포·Actions 재활성화는 별도 사용자 명령이 필요.
