# 한컴 및 Office PDF 변환 개발용 실험

이 코드는 **로컬 실험 단계**이며 웹 서비스나 운영 서버가 아니다. 클라우드 Worker에서 실행할 수 없고, API·업로드·큐·사용자 격리·외부 네트워크 차단·악성 파일 격리는 구현되지 않았다. 신뢰하지 않는 문서나 실제 고객 문서를 사용하지 말 것. 입력 파일은 네트워크에 전송되지 않지만 Office 엔진 내부의 외부 링크 접근 자체를 차단하는 샌드박스는 없다.

## 엔진 분리

- HWP/HWPX: Windows에 설치된 정식 한컴오피스의 COM 오토메이션 `Open` 및 `SaveAs(..., "PDF", ...)` 호출. 이 저장소에 한컴 프로그램이나 글꼴은 포함되지 않는다. 설치된 라이선스, 자동화 사용 권한 및 보안 모듈은 운영자가 별도로 확인·구성해야 한다. 본 개발 환경은 Windows/한컴이 없으므로 실제 실행은 미검증이다. 자동화 프로세스 중단·대화상자·거절 문서 처리와 격리를 해결하기 전 서버에 노출하지 않는다.
- XLS/XLSX, PPT/PPTX, DOC/DOCX: 별도 LibreOffice 프로세스의 Calc/Impress/Writer PDF 필터. 형식별 원본 fidelity는 실문서 대조 전 보장하지 않는다. 최초 실험 환경은 LibreOfficeDev 26.8 alpha이며, 운영 엔진으로 승인된 안정판이 아니다.
- JPG/PNG: 이 실험에서 다루지 않으며 기존 브라우저 이미지 엔진을 사용한다.

## 로컬 합성 문서 검사

`python -m unittest discover -s tests -v`는 임시 Excel 1쪽·PowerPoint 2쪽을 직접 만들고 PDF 쪽수, 텍스트, 표 글자, 이미지 객체와 Excel 벡터 객체 존재를 확인한다. 차트의 시각적 재현, 원본 대비 시각 충실도, xls/ppt/doc/docx 및 실제 업무 문서 시험은 별도다.

개발자가 인지한 문서로 수동 실행: `python scripts/office_pdf_probe.py sample.pptx output.pdf`. 원본 덮어쓰기는 차단하고 변환 임시 디렉터리는 종료 시 삭제한다. 사용자의 실문서는 저장소나 테스트 아티팩트에 추가하지 않는다.

## 웹 연동 전 필수 작업

1. 공식 한컴 제품/오토메이션의 상용 및 서버 이용 권한과 라이선스, Windows 전용 실행 환경 확보.
2. 안정적인 LibreOffice 버전 고정 및 Office 문서별 그림·표·차트·페이지·슬라이드 크기·폰트 검증.
3. 원본·출력 격리 보관, 접근권한, 암호화 전송, 보존/삭제 정책, 작업별 샌드박스와 자원·시간 제한, 매크로 및 외부 접속 차단, 잔여 프로세스 정리.
4. 사용자에게 원본이 서버에 전송된다는 사실을 명확히 알린 뒤 업로드/다운로드/취소/오류 처리를 실제 연결. 현재 웹은 브라우저에서만 처리하므로 그 개인정보 처리 방식과 충돌한다.
5. 실제 사용자 문서와 한컴/Excel/PowerPoint에서 저장한 기준 PDF를 페이지별로 대조. 없거나 재배포할 수 없는 글꼴은 정확히 표시한다. 임의 대체를 원본과 동일하다고 표시하지 않는다.

## 웹 연결 준비

`browser-local/src/remote-office-prototype.mjs`는 문서 파일을 같은 출처 `/api/v1/conversions`로 전송하고 PDF 응답을 검증하는 **미연결 클라이언트 초안**이다. 현재 서버 엔드포인트는 존재하지 않으며, UI에도 적용되지 않았다. 서버 연결 시 문서가 전송된다는 안내와 사용자 동작을 먼저 제공해야 한다. 서버 오류·취소와 PDF 형식 검사 테스트는 `node --test browser-local/tests/remote-office-prototype.mjs`로 독립 실행한다. 이 초안의 검사는 파일 안전성이나 출력 충실도를 보장하지 않는다.

## 공통 변환 처리 초안

`scripts/conversion_orchestrator.py`는 확장자를 기준으로 한컴과 LibreOffice 프로브를 선택하고, 임시 위치에 결과를 만든 뒤 PDF가 열리고 한 쪽 이상 존재하는지 확인한다. 검증 통과 전에 최종 파일을 만들지 않고 기존 파일도 덮어쓰지 않는다. 출력 검증은 원본 대비 레이아웃 일치나 누락 여부를 보증하지 않는다. Linux/POSIX에서 작업 프로세스 그룹을 구성해 시간 초과 시 해당 그룹을 종료하고, 작업의 임시 디렉터리를 상위 처리기가 정리한다. 프로세스 그룹에서 벗어난 별도 프로세스와 **Windows COM 서버 및 Windows 자식 전체 종료는 보장하지 않는다**. 운영 시 작업 격리와 자식 프로세스 정리를 별도 구현해야 한다. 업로드 API나 웹에 연결되어 있지 않다.

공통 처리 단위 검증: `python -m unittest discover -s tests -p test_conversion_orchestrator.py -v`. 어댑터 모의 실행을 사용하므로 한컴 실제 변환 성공을 뜻하지 않는다. PyMuPDF 설치가 필요하다.

## 로컬 요청부터 PDF 응답까지 시험

`scripts/local_conversion_api.py`는 **127.0.0.1에만 결합하는 개발용 HTTP 시험 장치**다. 길이 32자 이상의 개발용 토큰이 반드시 있어야 하고, 다른 Origin을 거부한다. 요청은 합성 시험을 위한 임시 32MiB 상한을 적용하며 운영 정책이 아니다. 요청당 임시 폴더에 입력을 두고 PDF 응답 후 삭제한다. 오류 응답에 문서명, 본문, 토큰을 넣지 않으며 로그 출력도 비활성화한다.

`python -m unittest discover -s tests -p test_local_conversion_api.py -v`는 토큰·입력 제한, 임시 폴더 삭제, 합성 PPTX를 이용한 로컬 API → LibreOffice → PDF를 검증한다. 추가로 Node에서 브라우저용 클라이언트 초안을 실행해 테스트용 헤더·주소 변환을 거쳐 같은 경로를 확인한다. **실제 브라우저/운영 웹의 Origin 정책과 인증을 검증한 것은 아니며, 해당 서버는 브라우저의 Origin 요청을 거부하므로 웹에서 직접 사용할 수 없다.**

이 장치는 단일 작업용 동기 테스트 코드이며 공개 서비스에 필요한 격리·인증·부하 제한·바이러스/매크로 정책·파일 및 응답 크기 운영 기준·브라우저 취소 연계·Windows COM 정리·데이터 보존 및 접근 통제를 제공하지 않는다. 개발 단계 합성 문서만 처리하고 외부 네트워크에 노출하거나 실제 고객 문서를 처리하지 않는다. 한컴 엔진과 Windows 경로는 시험되지 않았다.
